## 📁 Next.js 文件系统路由 — 完全手册

### 基本规则

```
src/app/ 下的每个文件夹 = URL 路径段
page.tsx  = 该路径的页面组件
layout.tsx = 该路径的布局（包裹 children）
```

## 一、基础路由

### 项目结构 → URL 映射

```
src/app/
├── page.tsx              → https://example.com/
├── about/
│   └── page.tsx          → https://example.com/about
├── blog/
│   ├── page.tsx          → https://example.com/blog        （列表页）
│   └── [id]/
│       └── page.tsx      → https://example.com/blog/123    （详情页）
├── dashboard/
│   ├── layout.tsx
│   ├── page.tsx          → https://example.com/dashboard
│   └── settings/
│       └── page.tsx      → https://example.com/dashboard/settings
└── shop/
    ├── category/
    │   └── [slug]/
    │       └── page.tsx  → https://example.com/category/electronics
    └── [...slug]/
        └── page.tsx      → Catch-all（后面讲）
```

## 二、动态路由 `[param]`

### 单个动态参数

```tsx
// src/app/blog/[id]/page.tsx
// URL: /blog/1, /blog/2, /blog/abc ...

interface PageProps {
  params: Promise<{
    id: string;  // 动态参数名必须与文件夹名匹配
  }>;
}

// ✅ 必须导出这个函数，告诉 Next.js 有哪些可能的 id
export async function generateStaticParams() {
  // 通常从数据库/API获取
  const posts = await fetch('https://api.example.com/posts').then(r => r.json());
  
  // 返回所有可能的参数组合
  return posts.map((post: any) => ({
    id: post.id.toString(),
  }));
  
  /* 返回格式：
  [
    { id: '1' },
    { id: '2' },
    { id: '3' },
  ]
  */
}

export async function generateMetadata({ params }: PageProps) {
  const { id } = await params;
  return {
    title: `Blog Post #${id}`,
    description: `Reading post ${id}`,
  };
}

export default async function BlogPostPage({ params }: PageProps) {
  const { id } = await params;

  // 服务端获取数据（SSR/SSG）
  const post = await fetch(`https://api.example.com/posts/${id}`).then(r => r.json());

  return (
    <article>
      <h1>{post.title}</h1>
      <p>Post ID: {id}</p>  {/* 从 URL 提取的参数 */}
      <div>{post.content}</div>
    </article>
  );
}
```

### 多个动态参数

```tsx
// src/app/products/[category]/[productId]/page.tsx
// URL: /products/electronics/42
// URL: /products/clothing/tshirt-red-xl

interface PageProps {
  params: Promise<{
    category: string;    // 第一层 []
    productId: string;   // 第二层 []
  }>;
}

export async function generateStaticParams() {
  return [
    { category: 'electronics', productId: '42' },
    { category: 'clothing', productId: 'tshirt-red-xl' },
  ];
}

export default async function ProductPage({ params }: PageProps) {
  const { category, productId } = await params;

  return (
    <div>
      <nav>
        <a href="/products">All Products</a> &gt;
        <a href={`/products/${category}`}>{category}</a>
      </nav>
      
      <h1>Product: {productId}</h1>
      <p>Category: {category}</p>
    </div>
  );
}
```

## 三、Catch-All Routes `[...slug]` — 捕获所有路径

```tsx
// src/app/docs/[...slug]/page.tsx
// 匹配：
//   /docs/getting-started           → slug = ['getting-started']
//   /docs/getting-started/install   → slug = ['getting-started', 'install']
//   /docs/api/users/create          → slug = ['api', 'users', 'create']

interface PageProps {
  params: Promise<{
    slug: string[];  // 注意：是数组！
  }>;
}

export default async function DocsPage({ params }: PageProps) {
  const { slug } = await params;

  // 将数组转为路径，用于查找文档
  const docPath = slug.join('/');  // "getting-started/install"

  return (
    <div>
      <aside>
        {/* 文档侧边栏 */}
        <a href="/docs/getting-started">Getting Started</a>
        <a href="/docs/api">API Reference</a>
      </aside>

      <main>
        <h1>📄 Documentation: {docPath || 'index'}</h1>
        {/* 根据 docPath 渲染对应文档内容 */}
        <DocContent path={docPath} />
      </main>
    </div>
  );
}
```

### 实际应用：你的 I18n 系统

你现在的项目就在用这个！

```
src/app/[locale]/page.tsx     → /en, /zh
src/app/[locale]/about/page.tsx → /en/about, /zh/about
```

## 四、可选 Catch-All `[[...slug]]`

```tsx
// src/app/shop/[[...categories]]/page.tsx
// 匹配：
//   /shop                           → categories = undefined（可选！）
//   /shop/electronics               → categories = ['electronics']
//   /shop/electronics/phones        → categories = ['electronics', 'phones']

export default async function ShopPage({ 
  params 
}: { 
  params: Promise<{ categories?: string[] }> 
}) {
  const { categories } = await params;

  if (!categories || categories.length === 0) {
    // /shop — 显示所有分类
    return (
      <main>
        <h1>All Products</h1>
        <CategoryList />
      </main>
    );
  }

  // /shop/electronics 或 /shop/electronics/phones
  return (
    <main>
      <Breadcrumb categories={categories} />
      <ProductList category={categories.join(' > ')} />
    </main>
  );
}
```

## 五、Layout 系统（嵌套布局）

### Layout 的核心规则

```
✅ 每个 page.tsx 必须被至少一个 layout.tsx 包裹
✅ 根 layout.tsx 必须包含 <html> 和 <body>
✅ Layout 会保持状态（不会重新渲染！）
✅ Layout 可以嵌套多层
```

### 你的项目的实际结构

```
src/app/
├── layout.tsx                    ← Root Layout (html/body)
│   └── [locale]/
│       ├── layout.tsx            ← Locale Layout (I18n Provider)
│       │   ├── page.tsx          ← /en 或 /zh
│       │   └── about/
│       │       └── page.tsx      ← /en/about 或 /zh/about
```

```tsx
// ====== Layer 1: Root Layout ======
// src/app/layout.tsx
import './globals.css';

export const metadata = {
  title: {
    template: '%s | My App',  // 子页面可以设置 %s 部分
    default: 'My App',
  },
};

export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <html lang="en">
      <body className="antialiased">
        {/* 这里的 children 是 [locale]/layout.tsx */}
        {children}
      </body>
    </html>
  );
}


// ====== Layer 2: Locale Layout ======
// src/app/[locale]/layout.tsx
import { I18nProviderClient } from '@/components/I18nProviderClient';
import enMessages from '@/messages/en.json';
import zhMessages from '@/messages/zh.json';

const messageMap = { en: enMessages, zh: zhMessages };

export default async function LocaleLayout({
  children,
  params,
}: {
  children: React.ReactNode;
  params: Promise<{ locale: string }>;
}) {
  const { locale } = await params;
  const messages = messageMap[locale as keyof typeof messageMap] || enMessages;

  return (
    <>
      {/* 全局 I18n Provider */}
      <I18nProviderClient locale={locale} messages={messages}>
        
        {/* 这里可以放 Header/Footer */}
        <Header />  {/* 所有 /en/* 和 /zh/* 页面都有 Header */}
        
        {/* children 是具体的 page.tsx */}
        <main>{children}</main>
        
        <Footer />

      </I18nProviderClient>
    </>
  );
}


// ====== Layer 3: 具体页面 ======
// src/app/[locale]/about/page.tsx
export default function AboutPage() {
  return (
    <section>
      <h1>About Us</h1>
      <p>We are a great company!</p>
    </section>
  );
}

/*
 * 最终渲染结果（以 /en/about 为例）：
 *
 * <html>
 *   <body>
 *     <I18nProviderClient locale="en" messages={...}>
 *       <Header />                 ← 来自 locale layout
 *       <main>
 *         <h1>About Us</h1>       ← 来自 about page
 *         <p>We are...</p>
 *       </main>
 *       <Footer />                ← 来自 locale layout
 *     </I18nProviderClient>
 *   </body>
 * </html>
 */
```

### Route Group `(group)` — 不影响 URL 的分组

```
问题：想给 /about 和 /team 用同一个 layout，但不想加 /marketing 前缀？

解决：用 ( ) 包裹文件夹名，不会出现在 URL 里！
```

```
src/app/
├── (marketing)/
│   ├── layout.tsx          ← 共享 marketing 布局
│   ├── about/
│   │   └── page.tsx        → /about （不是 /marketing/about！）
│   └── team/
│       └── page.tsx        → /team
├── (shop)/
│   ├── layout.tsx          ← 共享 shop 布局
│   ├── products/
│   │   └── page.tsx        → /products
│   └── cart/
│       └── page.tsx        → /cart
└── page.tsx                → /
```


## 六、特殊文件及其作用

| 文件名 | 作用 | 是否必需 |
|-------|------|---------|
| `page.tsx` | **唯一必填！** 定义该路径的 UI | ✅ 必需 |
| `layout.tsx` | 包裹子路由的 UI（sidebar/header） | 可选（但根目录必须有） |
| `loading.tsx` | 加载中显示的 UI（Suspense fallback） | 可选 |
| `error.tsx` | 错误边界，捕获运行时错误 | 可选 |
| `not-found.tsx` | 自定义 404 页面 | 可选 |
| `route.ts` | API 路由处理函数 | 可选 |
| `template.tsx` | 类似 layout，但每次导航都重新挂载 | 可选 |

## 七、Link 组件和导航

```tsx
import Link from 'next/link';
import { usePathname, useRouter, useSearchParams } from 'next/navigation';

function Navigation() {
  const pathname = usePathname();
  const router = useRouter();

  return (
    <nav>
      {/* ✅ 基础链接 — 自动 prefetch（默认行为） */}
      <Link href="/about">About</Link>
      
      {/* ✅ 动态链接 */}
      <Link href={`/blog/${postId}`}>Read Post</Link>
      
      {/* ✅ Active 状态高亮 */}
      <Link 
        href="/dashboard" 
        className={pathname.startsWith('/dashboard') ? 'active' : ''}
      >
        Dashboard
      </Link>
      
      {/* ✅ 编程式导航 */}
      <button onClick={() => router.push('/login')}>
        Login
      </button>
      
      {/* ✅ 替换历史记录（不产生后退） */}
      <button onClick={() => router.replace('/new-page')}>
        Go (no back)
      </button>
      
      {/* ✅ 刷新当前页面 */}
      <button onClick={() => router.refresh()}>
        Refresh Data
      </button>
    </nav>
  );
}
```

## 九、对比 Vite + React Router 写法

| 场景 | Next.js 文件路由 | Vite + React Router |
|------|-----------------|-------------------|
| **定义路由** | 创建文件夹+`page.tsx` | 手动写 `<Route>` 配置 |
| **嵌套路由** | 文件夹自动嵌套 | `<Outlet>` + 配套配置 |
| **动态参数** | `[id]` 文件夹 | `:id` 字符串 |
| **404 处理** | `not-found.tsx` | `<Route path="*">` |
| **Layout** | `layout.tsx` | 布局组件包裹 |
| **加载状态** | `loading.tsx` | 自己写 Suspense |

### Vite 版本的等效写法

```tsx
// Vite + React Router 需要这样写（手动配置一切）

// router.jsx

  {
    element: <RootLayout />,
    children: [
      { index: true, element: <HomePage /> },

          { path: 'products/:id', element: <ProductDetail /> },

      },
      { path: 'login', element: <LoginPage /> },
      {
        path: 'account',
        element: <AccountLayout />,
        children: [
          { index: true, element: <AccountPage /> },
          { path: 'orders', element: <OrdersPage /> },
        ],
      },
    ],
  },
]);

// 还需要处理 lazy loading...
// 还需要处理 suspense boundary...
// 还需要处理 error boundary...
```
